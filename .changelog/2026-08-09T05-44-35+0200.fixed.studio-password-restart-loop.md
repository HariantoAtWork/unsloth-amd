Clear `UNSLOTH_STUDIO_PASSWORD` before launching Studio once the admin password is already finalized.

Unsloth treats that env var as initial `--password` only; re-supplying it after setup exits with code 1 and caused `unsloth-builder` to restart-loop. The value is kept for API login/watcher use. Planner/builder now take the password from `.env` like the main service, and `docker-studio.sh` is bind-mounted so the fix applies without a rebuild.
